问题：chat-tabs/tab.tsx:129 运行中把关闭 X 换成 spinner——用户只能靠 ⌘W 或右键菜单才能关掉正在跑的会话，跟 idle/error 的 tab 行为不一致，找不到关闭入口。
现状 · 运行中的 tab问题
会话 1 ✕ 会话 2 · 重构 ✕ 被 spinner 顶掉了 会话 3 ✕
运行中的 tab 上只有 spinner，没有 ✕；想关掉它只能 ⌘W 或右键。

优化 · spinner 与关闭按钮并存建议
会话 1 ✕ 会话 2 · 重构 ✕ 会话 3 ✕

方案：状态指示与关闭操作解耦——spinner 放状态位，✕ 保留在尾部（hover 时加深）；点击时若在运行，先确认"停止此任务并关闭"。

暗色模式冷启动白屏闪烁（设计文档自认的 known gap）

问题：App.tsx:365-373 主题在 React 首帧之后的 useLayoutEffect 才应用；index.html 没有内联脚本、 main.tsx 挂载前也没设 .dark。暗色用户在 webview 冷启动时会先看到亮色 #fafafa 首帧再闪成暗色。 （design.md §4 明确标注为 known gap。）
现状 · 暗色用户冷启动问题
循环演示：第一帧是亮的 #fafafa，随后才跳到暗色 #17191c。
用户视角：深夜打开 App 被"闪瞎"一下，像是 bug，也削弱桌面 App 的质感。
优化 · 挂载前内联脚本预设主题建议
第一帧就是暗色——首帧不再闪烁。
<head>
  <script>
    // 在 CSS/React 挂载前同步设置 .dark，避免首帧白闪
    var t = localStorage.getItem("agentre.theme");
    if (t === "dark" || (t !== "light" && matchMedia("(prefers-color-scheme: dark)").matches)) {
      document.documentElement.classList.add("dark");
      document.documentElement.dataset.theme = "dark";
      document.documentElement.style.colorScheme = "dark";
    }
  </script>
</head>
方案：在 index.html 的 <head>、模块脚本之前放一段内联脚本，读取 localStorage + prefers-color-scheme 预设 .dark。改动最小、收益立现。
