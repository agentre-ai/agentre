# 会话文件面板 UX 精修：Git 提升顶层、路径压缩、右键菜单与多标签预览

> Status: Draft
> Owner: chat experience（前端 + desktop 后端 + agentred daemon）
> Last updated: 2026-08-09

**Objective:** 让会话右侧文件面板在 240px 宽度里更快找到文件、更少被 chrome 与长路径挤占，并支持同时预览多个文件。

**Hard invariants:**

1. **本面板绝不修改工作区或 git 状态。** 新增的递归搜索与「在文件管理器中显示」同样只读；后者只唤起系统文件管理器，不写任何文件，也不得为算行数执行 `git add -N` 或任何写索引的命令（沿用 `docs/specs/2026-08-07-session-files-three-modes.md` 硬不变量 2）。
2. **目录列举、递归搜索与文件读取都不得越出会话工作目录。** 请求路径与搜索根解析后必须仍在 cwd 之内，否则拒绝。
3. **新增可见 UI 文案全部走 i18n**，同时覆盖 `zh-CN` 与 `en`，由 `frontend/src/__tests__/i18n.test.ts` 校验。
4. **不改动既有 `remotefs.*` 与 `workspacefs.*` RPC 的请求/响应形状**；新能力一律新开方法，让版本偏斜在旧 daemon 上表现为「方法不存在」而不是静默降级。
5. **本地会话与远端 agentred 会话行为一致**，差别只限于本机独占能力（用系统应用打开、在文件管理器中显示、复制绝对路径）。

**本轮显式取代的既有约定：** `docs/specs/2026-08-07-session-files-three-modes.md` 的硬不变量 1 规定「变动」模式行点击必须跳转到 `lastTurn` 对应轮次且零回归。本轮按用户决定（2026-08-09）取代它——见决策 5。该 spec 的其余硬不变量继续成立。

## Problem

1. **两层 tab 叠放，常驻 chrome 吃掉 96px。** 顶层 `h-9`（`tab-bar.tsx:20`）+ 模式切换 `h-8`（`files-mode-switcher.tsx:34`）+ 上下文条 `h-7`（`views/files-panel.tsx:57`）在 240px 宽的面板里连续压三条。「嵌套 tab」本身也让「变动 / 目录 / Git」看起来比「大纲」低一级，而 Git 恰恰回答着最高频的问题——这一轮 agent 到底改了什么。
2. **三种模式的行点击语义互不相同。** 变动模式整行点击跳回对应轮次（`views/files-view.tsx:144`），Git 模式整行点击用系统应用打开（`views/git-view.tsx:147`），目录模式的文件行是纯 `<div>`、**既不可点也不可聚焦**（`views/directory-view.tsx:181`）。同一批文件、三种行为，其中一种还是死的。
3. **每行右端两个常驻图标按钮吃掉约 48px。** `Eye` + `ExternalLink` 在 `views/files-view.tsx:159-183` 与 `views/directory-view.tsx:189-213` 恒常渲染，占 240px 的 20%；实测 `use-git-changes.ts`、`git-context-bar.tsx` 这类真实文件名在该宽度下已被截断。
4. **单子目录链每段各占一行。** 变动模式的 `deriveFileTree`（`derive.ts`）与目录模式的逐层懒加载都按单段目录建节点，`internal/service/chat_svc/turn.go` 一个文件就要 4 行 + 42px 缩进。「单子目录链压缩」在上一轮 spec 被明确列为 out of scope，至今没做。
5. **预览一次只能开一个文件。** `chat-sidebar-store.ts:30` 的 `previewBySession` 每个会话只存一个 `FilePreviewSelection`，打开新文件即替换。对照阅读两个文件只能来回切，且切走后档位与滚动位置都不保留。
6. **目录模式既看不出 git 线索，也看不出文件类型。** `views/directory-view.tsx:184` 对所有文件行渲染同一个 `FileCode` 图标，且不带任何状态或角标——目录树只能用来找文件，无法回答「这里面哪些被动过」。
7. **大仓库里没有按名字找文件的途径。** 目录树只能逐层点开（决策 6 的懒加载是必要的），但没有任何搜索入口，用户要定位一个已知文件名仍得离开应用。
8. **面板没有右键菜单、没有键盘导航，长路径也拿不出来。** 全仓 `role="tree"` 零命中，树是一串平行 `button`，键盘用户要按几十次 Tab 才能到列表底部；长路径只有原生 `title`（约 1s 延迟、无样式、不可选中），想把路径贴到别处只能手抄。

## Actors and user stories

1. 作为查看 agent 工作成果的用户，我希望一次点击就看到本次的 git 变动，而不是先进「文件」页再切模式。
2. 作为在 240px 侧栏里工作的用户，我希望文件名完整可读，而不是被两个常驻按钮和多级缩进挤到截断。
3. 作为在做对照阅读的用户，我希望同时打开多个文件的预览并在它们之间切换，而不是每次都替换掉上一个。
4. 作为要把文件路径贴到别处（终端、对话框、issue）的用户，我希望能直接复制相对或绝对路径。
5. 作为键盘用户，我希望用方向键在文件列表里移动、回车预览，而不是按几十次 Tab。
6. 作为大仓库用户，我希望输入文件名片段就能找到文件，而不是逐层展开目录树。
7. 作为审阅改动的用户，我希望在目录树上直接看出哪些文件被动过，而不必在目录与 Git 两个视图之间反复对照。

## Design decisions

| # | Decision | Basis and rejected option |
|---|---|---|
| 1 | 顶层改为「大纲 / 文件 / Git」三个 tab，Git 提升一级；「变动 / 目录」作为「文件」页内的两档保留 | 用户决定（2026-08-09）。mockup B 取证：提升后大纲页 chrome 36px、文件页 68px、Git 页 64px，均从 96px 下降，且只剩一层 tab。上一轮决策 1 拒绝提升时的理由是「Git 子档与基线仍要另占一行，并没省掉 chrome」——该推理漏算了模式切换行会整条消失。拒绝：四个平级 tab（把「变动」也提上来）——mockup A 取证英文下已放不下三个带计数的 tab，四个必然溢出 |
| 2 | 顶层 tab 去掉图标，只保留文案 + 计数，等宽 `flex-1` | mockup A 取证：A1（照搬现状的图标+文案+计数）中文恰好塞下、英文 `Outline` 溢出；A3（保图标改等宽）英文下 `Outline` 被截成 `Outli…`；A2（去图标）在 240px 与 190px、中英双语下都完整不换行。拒绝：保留图标并砍掉计数——计数是「有没有变动」的零成本信号，比图标更有信息量 |
| 3 | 「显示忽略项」从带文字 Toggle 缩成纯图标，与新的搜索入口一同并入「变动 / 目录」子档行右端 | mockup B1 与 G1 取证：两档胶囊组约 84px，两个图标共 48px，240px 下余量充足。这样「文件」页的**常驻** chrome 保持两行，搜索输入框只在激活时占第三行。拒绝：给搜索单开一条常驻行——会把决策 1 刚省下的 chrome 原样还回去 |
| 4 | 变动与目录两个树形模式实施单子目录链压缩：只含一个子目录、不含文件的链折成一行 | mockup C 取证：同一批 3 个文件从 10 行降到 5 行，最深缩进从 56px 降到 14px，文件名可用宽度翻倍。链前缀降透明度、末段保持正常权重，用来分辨「这个节点到底是谁」。拒绝：继续把它留在 out of scope——它是长路径问题的最大单项杠杆 |
| 5 | 三种模式的行点击语义统一为「单击 = 预览」；「跳到对应轮次」降级为变动模式右键菜单的一项 | 用户决定（2026-08-09），显式取代上一轮硬不变量 1。预览是三种模式下都成立且最高频的意图；统一后目录模式的行从「完全不可点」变为可点，是纯增益。拒绝：只统一目录与 Git、变动保留跳轮次——三种行为里仍留两种，用户得记住哪一档点了会跳走 |
| 6 | 撤掉行内的 `Eye` 与 `ExternalLink` 常驻按钮，换成一个 24px、**恒占位**、仅在 hover 或键盘聚焦时显形的 `⋯` 菜单按钮 | mockup D 取证：240px 下三个真实文件名从「两个被截断」变为全部完整。槽位必须恒占位、只切换可见性，否则 hover 会让整行文字左右跳。聚焦时同样显形，保证右键菜单有键盘入口、不是纯鼠标能力。拒绝：hover 时才插入按钮——布局抖动；拒绝：只留右键、不留 `⋯`——右键在桌面端可发现性低，且触控板用户成本高 |
| 7 | 右键菜单用 shadcn `ContextMenu`，交互与分组照 `chat-tabs/tab-strip.tsx:205-252` 的既有用法 | 该文件是仓库里 `components/ui/context-menu` 的现有业务用例（`ContextMenuTrigger` 包裹行、`ContextMenuItem` + `ContextMenuSeparator` 分组），照它做可以让两处右键行为一致。拒绝：自建 Popover 模拟右键——会丢掉 Radix 已处理的定位、焦点陷阱与 Esc 语义 |
| 8 | 远端会话下，本机独占的菜单项**整项不渲染**而非置灰 | 沿用既有取舍：「打开文件」按钮本来就只在本地会话且 cwd 非空时渲染（`views/files-view.tsx:79`）。置灰会让用户反复去点一个永远不可用的项。拒绝：置灰并加解释 tooltip |
| 9 | 「在文件管理器中显示」新增一个 Wails 绑定，复用 `validateOpenPath` 的校验与 `runOpenCmd` 测试缝 | 用户决定（2026-08-09）。现有 `internal/app/system.go:29` 的 `OpenPath` 只能「用默认应用打开」，无 reveal 能力；`runOpenPlatform` 的三平台分派与 `runOpenCmd` 的替换缝（`system.go:17`）已被 `TestOpenPath_dispatchesPlatformCommand` 覆盖，新绑定按同一形状扩展。拒绝：复用 `OpenPath` 打开父目录——那会丢掉「选中该文件」这个全部价值 |
| 10 | 预览标签沿用 `chat-tabs-store` 已确立的临时/固定语义：至多一个临时标签、原地替换、双击或右键「固定」转常驻 | `stores/chat-tabs-store.ts` 已实现 `isPreview` / `isPinned` / `promoteCurrent`，`chat-tabs/tab-strip.tsx` 已实现对应的右键菜单。同一个应用里两套标签语义不同会直接制造困惑。拒绝：全部常驻 + LRU 淘汰——浏览目录树时标签会迅速堆满 |
| 11 | 标签条只在标签数 ≥ 2 时渲染 | mockup F4 取证：单文件时与现状完全一致，不为多标签能力给单文件用户白加一行 chrome。拒绝：标签条恒常渲染——单文件是最常见情形，为它常驻 34px 换不到任何信息 |
| 12 | 标签按会话持久化且跨重启存活；每会话上限 8 个标签，全局只保留最近 20 个会话的标签表 | 用户决定（2026-08-09）。上限与全局淘汰是持久化的必要代价：`previewBySession` 已随 `chat-sidebar-store` 落 localStorage，不设界会随会话数无限增长。拒绝：不设上限 |
| 13 | 目录模式叠加 git **状态**（文件名着色 + 状态字母、目录行显示子树变动数），但**不显示** `+N/−N` 角标 | 用户决定纳入（2026-08-09）；mockup H 取证：H1（状态字母 + 角标 + `⋯` 槽位三者共存）在 240px + 缩进下把文件名重新挤到截断，抵消了决策 4 与 6 的收益。目录树的首要职责是找文件，行数留给 Git 页与变动页回答。拒绝：目录模式与 Git 页完全同款行 |
| 14 | 文件搜索走**后端递归遍历**，匹配 basename 的不区分大小写子串 | 用户决定纳入（2026-08-09）。前端只能过滤「已展开的层」，而用户要找的恰恰是没展开的那些，等于没有搜索。遍历时按 `.gitignore` 剪枝（`node_modules` 这类目录整棵跳过）才是大仓可用的前提。拒绝：`git ls-files`——非 git 目录不可用，且看不到 agent 刚创建的未跟踪文件，与上一轮决策 6 拒绝它的理由一致。拒绝：模糊匹配——需要打分排序，且 240px 里无法展示匹配依据 |
| 15 | 搜索结果放弃树形，改用 Git 页那套「basename + 头截断目录后缀」的扁平行 | mockup G2 取证：搜索命中天然跨目录，树形下每个命中都要拖出一整条祖先链。与上一轮决策 11 让 Git 页扁平化的理由相同 |
| 16 | 列表改用 `role="tree"` / `treeitem` + roving tabindex：整个列表是一个 Tab 停靠点，内部用方向键移动 | 用户决定纳入（2026-08-09）。现状是一串平行 `button`，键盘用户要按几十次 Tab；roving tabindex 是 WAI-ARIA 对树形控件的既定模式。拒绝：只给列表加快捷键、不改语义——读屏软件仍会把它读成一堆按钮 |
| 17 | 文件图标按扩展名分类，分类表复用 `chat-context-sidebar/previewable.ts` 已有的 markdown / image / code 判定 | 用户决定纳入（2026-08-09）。该文件已维护着扩展名 allowlist，再开一张表必然漂移。拒绝：新建独立的图标扩展名表 |
| 18 | 在 `e2e/tests/` 增加一条**提交的** Playwright spec，覆盖「Git 顶层 tab → 单击行 → 开两个标签 → 切换」这条跨侧栏与预览面板的链路 | 用户决定（2026-08-09）。`e2e/README.md` 第 1 节写明「提交 spec 的门槛很高，只收核心流程」，本条是**有意识地**突破该门槛：本轮重写了文件面板的整个 IA 与两个面板之间的接线，而这条接线跨越 store、侧栏、预览面板三处，单测各自 mock 后正好覆盖不到它们的接合处。拒绝：只靠 `e2e/scratch/` 的一次性验证——用完即弃，留不下回归护栏 |

## 顶层导航与页面 chrome

顶层 tab 由「大纲 / 文件」改为「大纲 / 文件 / Git」三段，各段等宽、不带图标，显示文案与计数：大纲显示轮次数、文件显示 `deriveFiles()` 的文件数、Git 在其数据已加载时显示变动文件数（未加载或加载中不显示）。任一时刻恰有一段选中，选中段以强调背景 + 主色文字区分，沿用 `role="tablist"` / `aria-selected`，可 Tab 聚焦且焦点环可见。选中的顶层 tab 随现有侧栏 store 持久化；持久化值非法或缺失时回落到「大纲」。

「文件」页内保留「变动 / 目录」两档，以胶囊组呈现，与 Git 页的「未提交 / 本分支」两档同形。该行右端依次是「显示忽略项」与「搜索」两个纯图标按钮，都只在「目录」档出现；「显示忽略项」表达按下状态，「搜索」在过滤激活时表达按下状态。

「Git」页的上下文条与现状一致：左侧「未提交 / 本分支」两档，选中「本分支」时右侧出现常驻的基线分支按钮。工作目录不是 git 仓库时整条上下文条收起。

据此，各页的常驻 chrome 为：大纲页一行、文件页两行、Git 页两行（非 git 仓库时一行）。搜索输入框是**临时**的第三行，仅在过滤激活期间存在。

侧栏被拖窄到 190px 时，顶层三段与两档胶囊均不换行。

## 行的形态与交互

**统一的点击语义。** 三种模式下，单击一个可预览的文件行 = 在预览面板中打开它（作为临时标签，见「多标签预览」）。当前正被预览的行以强调背景高亮。

**不可预览的文件行**（扩展名不在 `previewable.ts` 的 allowlist 内，或路径解析后落在 cwd 之外）不响应单击，也不显示 hover 高亮，但仍可右键、仍有 `⋯` 菜单按钮——路径复制与「用默认应用打开」对这类文件依然有意义。这是刻意的：让「能不能点」在视觉上就可预期，好过点下去没反应或弹出一个只会说「不支持预览」的标签。

**目录行**单击展开 / 收起，行为与现状一致。

**行右端**是一个 24px 的 `⋯` 菜单按钮槽位。槽位恒占位，仅在该行 hover 或获得键盘焦点时显形；点击它打开与右键相同的菜单。行内不再有其他常驻图标按钮。

**行的组成**（自左至右）：缩进、展开箭头或等宽占位、类型图标、名称、模式特有的信息、`⋯` 槽位。名称的收缩优先级最低——先被挤压的永远是目录后缀一类的次要信息。

## 路径展示

**树形模式的链压缩。** 变动与目录两种模式下，只包含一个子目录且不直接包含文件的目录链，折叠为一行显示，形如 `internal/service/chat_svc`。链中除末段外的前缀降低不透明度，末段保持正常文字权重，使该节点的身份一眼可辨。压缩后的行作为一个整体展开 / 收起，其子项缩进只增加一级。

链行本身放不下时**从头截断**（保留末段），与 Git 页目录后缀的截断方向一致——尾部才是身份信息。

**Git 页与搜索结果的扁平行**沿用现有形态：状态字母、basename、灰色目录后缀（从头截断）、diff 角标。目录后缀的收缩权重最大，因此文件名实际上永不被截断。

**完整路径的获取途径**是右键菜单的三个复制项，不再依赖 tooltip。行仍保留原生 `title` 作为悬停时的兜底。

## 右键菜单

三种模式的文件行、目录模式的目录行、以及预览标签，各有一份右键菜单；`⋯` 按钮打开的菜单与右键完全相同。菜单按语义分组，组间以分隔线区隔。

**文件行**的菜单依次是：预览 / 在新标签页预览；（仅变动模式）跳到对应轮次；用默认应用打开 / 在文件管理器中显示；复制相对路径 / 复制绝对路径 / 复制文件名。

**目录行**的菜单依次是：展开或收起；在文件管理器中显示；复制相对路径 / 复制绝对路径。

**预览标签**的菜单依次是：固定标签（已固定时为取消固定）；关闭 / 关闭其他 / 全部关闭；复制相对路径。

**远端会话**下，「用默认应用打开」「在文件管理器中显示」「复制绝对路径」三项整项不渲染。**不可预览的文件**上，「预览」与「在新标签页预览」两项整项不渲染。

复制成功后给出一条轻量成功提示；复制失败（剪贴板不可用）给出错误提示。「在文件管理器中显示」失败时给出错误提示，文案包含系统返回的原因。

## 在文件管理器中显示

新增一个 Wails 绑定，接受一个绝对路径，在系统文件管理器中打开其所在目录**并选中该文件**。入参校验与 `OpenPath` 完全一致：必须是绝对路径、不得含 `..` 段、末尾的 `:line[:col]` 后缀先行剥离。三个平台各自唤起对应的文件管理器命令；平台命令不可用或返回非零时，绑定返回错误，由前端提示。

该绑定与 `OpenPath` 一样只在本地会话被调用，远端会话下菜单项不渲染，因此不存在「拿远端路径调本机命令」的路径。

## 目录模式的 git 状态叠加

「目录」档在拉取目录内容的同时取得当前工作区的 git 变动清单（与 Git 页的「未提交」档同一份数据），把状态叠加到树上：

- **文件行**：被修改 / 新增 / 删除 / 重命名 / 未跟踪的文件，其文件名按对应状态着色，并在名称右侧显示状态字母；状态字母对读屏隐藏，另给文字标签。未变动的文件不着色、不显示字母。
- **目录行**：右端显示其子树内变动文件的数量，用状态色；数量为零时不显示。链压缩后的行按整条链的子树统计。
- **不显示** `+N/−N` 角标。

工作目录不是 git 仓库、或 git 变动读取失败时，目录树照常渲染，只是不带任何状态叠加——状态是增强信息，它的缺失不能让目录模式不可用。

文件图标按扩展名分为 markdown、图片、代码 / 文本、以及不在 allowlist 内的通用文件四类，分类判定复用既有的可预览性判定。目录图标不变。

## 文件搜索

「目录」档的搜索按钮切换过滤态。激活时，子档行下方出现一行输入框，内含放大镜、输入区、命中计数与清除按钮，焦点自动落入输入区；关闭过滤态或清空输入即回到树形视图，树的展开状态不受影响。

输入变化后经防抖发起一次后端递归搜索，入参是会话 id、查询串、是否包含被忽略项（取自「显示忽略项」开关的当前值）。匹配规则是 basename 的**不区分大小写子串**匹配。遍历从会话工作目录开始，`.git` 恒不进入；未开启「显示忽略项」时，被 git 忽略的目录整棵剪枝、被忽略的文件不计入。

结果以扁平列表呈现，每行是 basename + 头截断的目录后缀，命中的子串高亮；行的点击、`⋯` 菜单与右键菜单与其他模式完全一致。

命中数超过上限时截断，并在列表末尾显示说明，说明里带上实际上限数字。查询串为空时不发起搜索，显示提示引导输入。无命中时显示空态，并说明被忽略的文件默认不参与搜索。搜索期间显示加载态；失败时显示错误态与重试按钮。

搜索调用受上下文超时约束；遍历另有目录数预算，触及预算时按「已截断」处理并给出同样的说明——不静默返回不完整结果。

远端会话走同一个绑定，由服务层选择 RPC 传输；daemon 侧新增对应方法，要求已鉴权。旧版 daemon 不认识该方法时，显示「远端 agentred 版本过旧」提示，与既有的版本偏斜提示一致。

## 多标签预览

预览面板从「每会话一个选中文件」改为「每会话一组标签」。

**打开语义**沿用应用内既有的标签语义：单击文件行打开的是**临时标签**，任一时刻至多一个，再次单击别的文件会原地替换它；双击文件行、或在标签 / 文件行的右键菜单选「在新标签页预览」「固定标签」，把它转为常驻标签。已打开的文件被再次点击时，激活既有标签而不是新建。

**标签条**位于预览面板 header 之上，仅在标签数 ≥ 2 时渲染。每个标签显示类型图标、文件名与关闭按钮；临时标签的文件名以**斜体**区分（颜色已被主色与状态色占满，不再承载这一层含义）。活动标签以背景提亮加顶部主色条区分。标签等比收缩到下限后不再缩，改为横向滚动，右端出现常驻的溢出菜单，可列出全部标签并直接切换；活动标签始终自动滚入可见区。

**header** 的职责不变：显示当前活动文件的图标、文件名、目录路径、markdown 的三档分段控件与关闭按钮。标签条回答「打开了哪些」，header 回答「当前这个是什么、怎么看」。

**关闭**：关闭活动标签后激活右侧相邻标签，没有右侧则激活左侧；关闭最后一个标签时整个预览面板收起。header 的关闭按钮关闭的是当前活动标签。

**上限与淘汰**：每个会话最多 8 个标签。已达上限时新开标签会淘汰最久未被激活的**未固定**标签；若 8 个全部已固定，则不新开标签，并提示需要先关闭一个。

**持久化**：标签集合、各自的固定态与活动标签按会话持久化，跨应用重启存活。全局只保留最近 20 个会话的标签表，超出时按「该会话标签最后一次被激活的时间」淘汰整个会话条目。持久化值非法、缺失或指向已不存在的会话时整条丢弃。

重开时文件可能已被删除或移动：该标签**照常保留**，正文显示既有的读取失败态与重试按钮。自动关闭这类标签会让用户以为标签丢了，反而更难排查。

markdown 的档位是标签自身的状态，切换标签时各自保留；同一模式内的既有档位规则不变。

## 键盘与无障碍

文件列表作为整体是一个 Tab 停靠点，内部语义为 `role="tree"` / `role="treeitem"`，采用 roving tabindex：`↑` / `↓` 在可见行间移动焦点，`→` 展开目录行（已展开则移入首个子项），`←` 收起目录行（已收起则移到父行），`Home` / `End` 跳到首 / 末行，`Enter` 对文件行执行预览、对目录行执行展开收起，`Shift+F10` 或菜单键打开该行的右键菜单。行的展开态由 `aria-expanded` 表达，层级由 `aria-level` 表达。

预览面板中，`Esc` 关闭当前活动标签。标签条本身是 `role="tablist"`，`←` / `→` 在标签间移动。

三处分段控件（顶层 tab、文件页两档、Git 页两档）均用 tablist / tab 语义表达选中状态。搜索输入框有可访问名称，命中计数以文本表达。git 状态字母对读屏隐藏并另给文字标签；状态着色不单独承载信息——字母与标签始终同在。加载、截断、空态、错误态均有文本表达。

新增可见文案覆盖：Git 顶层 tab 名、搜索入口与输入框占位符、命中计数、搜索空态与截断说明、搜索加载与失败、右键菜单的全部项（预览 / 在新标签页预览 / 跳到对应轮次 / 用默认应用打开 / 在文件管理器中显示 / 复制相对路径 / 复制绝对路径 / 复制文件名 / 展开收起）、复制成功与失败提示、reveal 失败提示、标签上限提示、目录行子树变动数的无障碍标签、以及 `⋯` 按钮的无障碍标签。已有等价含义的文案（固定 / 取消固定 / 关闭 / 关闭其他）复用 `chat-tabs` 既有的 key，不另建。全部同时写入 `zh-CN` 与 `en`。

## 失败与恢复

会话没有工作目录时，「目录」与「Git」两页显示各自的空态，「变动」不受影响；搜索入口在无 cwd 时不渲染。

git 变动读取失败只影响目录模式的状态叠加与 Git 页本身，不影响目录树与搜索。单层目录读取失败仍只让该节点显示一行错误，树的其余部分照常可用。

远端设备离线、租借失败或超时时，对应视图显示错误态与重试按钮，重试只重发当前视图的请求，不影响其他视图已缓存的数据。

剪贴板写入失败、reveal 命令失败均以提示呈现，不改变面板状态。

## Out of scope

- **在面板内执行任何 git 写操作**（暂存、提交、丢弃、切分支）。
- **行级 diff 视图与文件内容编辑。** 预览仍是只读。
- **预览标签的拖拽重排。** `chat-tabs` 有，本轮预览标签不做——标签上限只有 8，顺序价值有限。
- **模糊匹配与文件内容全文搜索。** 本轮搜索只匹配 basename 子串。
- **「大纲」页的任何改动**，包括其派生逻辑、高亮与滚动跟随。
- **「变动」模式的派生逻辑**（`deriveFiles`）本身：本轮只改它的渲染形态与交互，不改它从消息里认哪些文件。
- **`chat_svc.GetSessionGitState` 的迁移或补远端实现。** 它至今在前端零调用，与本轮无关。
- **行号定位打开**（`OpenPath` 现有的 `:line` 剥离行为不变）。
